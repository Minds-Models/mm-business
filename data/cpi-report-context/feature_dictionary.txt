================================================================================
COMPOSITE DATASET — FIELD DICTIONARY (plain-text extract, verbatim descriptions)
================================================================================

Dataset:  ops/cpi-combined/data/joined.jsonl  (54,092 records, one JSON object
per line, one line per visitor)

This file documents the EXACT meaning of every field present in that dataset.
Descriptions marked "verbatim" are copied unmodified from the source schema
Field(description=...) strings — these are the literal instructions given to
the vision model that produced the value, i.e. the ground truth for what the
value means. Two independent source schemas feed this dataset:

  GOLDEN  = analysis-api's structured Gemini output schema
            file: analysis-api/libs/analyzer/schema.py
            (auto-generated from config/golden/009-C29/{perception,gestalt}/schema.json)
            column names below are the analysis-api "normalized" column
            names (see analysis-api/libs/datalayer/transforms/normalize.py,
            _SECTION_MAP), NOT the short schema.py field names — the mapping
            from schema.py short key -> column name is given for every field
            below as "schema key".

  BD      = brand-extractor's structured Gemini output schema
            file: brand-extractor/brand_detector/schema.py
            class Detection (garments[], accessories[], carried_items[],
            person, trip). Composite dataset columns are prefixed bd_.

Every GOLDEN and BD field below was independently produced by a Gemini
structured-output call reading the SAME stored visitor photo (face
pre-anonymized) — GOLDEN via two calls (perception + gestalt), BD via one
call. They are two separate reads of one image, not two measurements of
different things, except where noted.

Encoding notes (apply throughout):
 - GOLDEN boolean fields are stored as integer 1 / 0 / NULL (NULL = "not
   observed", not false). BD boolean fields are native JSON true / false /
   null (null = "torso not visible" etc., not false) — do not treat GOLDEN
   NULL and BD null as the same "no signal" reason without checking the
   field description; the two schemas use it differently in places.
 - GOLDEN enum fields carry an explicit closed value list; a value outside
   that list should not occur. Most GOLDEN enums include their own
   "unknown" member (the model's own "cannot tell" answer), which is
   distinct from a NULL/missing field.
 - BD enum fields carry their own closed value list ending in "unclear"
   instead of "unknown" — same role, different literal spelling. Do not
   assume the two zero-signal sentinels are the identical string.
 - BD's `type` field (inside every bd_items entry) is FREE TEXT lowercase
   snake_case, not a closed enum — see note C3 below.
 - GOLDEN brand-type free-text fields do not appear in this dataset at all
   (superseded by bd_items — see "fields intentionally absent" at the end
   of this file); the only free text worth noting is BD's `brand` field
   inside bd_items.

================================================================================
SECTION A — IDENTIFIERS & TIMING
================================================================================

person_id
  UUID. Primary key / join key. Same person_id used across all upstream
  tables (visitors_v2, visitors_normalized_v2, brand-detector's per-visitor
  result file <person_id>.json).

entered_at
  Timestamp, UTC, ISO-like string with fractional seconds and a "+00"
  offset (e.g. "2026-09-08 16:51:53.970901+00"). Camera-session start time
  for this visitor, taken from the raw visitors_v2 row — NOT re-derived or
  altered by the join.

left_at
  Timestamp, UTC, same format as entered_at. Camera-session end time.

hour
  Integer 0-23. Hour of entered_at converted to local time, zone
  Europe/Prague (source store's timezone). Derived field, computed by the
  join script (ops/cpi-combined/build_joined.py), not present upstream.

day_of_week
  String, full English weekday name (e.g. "Tuesday"). Local-time weekday of
  entered_at, Europe/Prague. Derived by the join script.

is_weekend
  Boolean. True if local weekday (Europe/Prague) is Saturday or Sunday.
  Derived by the join script.

B1. Demographics & individual activity — schema.py class Demographics (section "1")
--------------------------------------------------------------------------------

age            [schema key: age]
  Values: 10s | 20s | 30s | 40s | 50s | 60s+ | unknown
  Verbatim: "Read the decade age bracket from the image; use facial
  features, skin texture, hair colour and texture, and body proportions as
  cues; 60s is open-ended (60+); unknown if age cannot be confidently
  estimated from visible cues. 10s=teens — smooth skin, no facial ageing,
  youthful facial proportions; 20s=twenties — mature facial structure with
  no visible ageing markers; 30s=thirties — early fine lines, fuller facial
  definition than twenties; 40s=forties — visible fine lines, softening
  jawline, early greying possible; 50s=fifties — established lines, common
  greying, clear loss of jawline definition; 60s+=sixty and over — deep
  lines, substantial greying or white hair, visible skin laxity;
  unknown=face not in frame or genuinely unreadable; do not use when a
  reasonable bracket is apparent"

ageOnEdgeGenerated
  Boolean, stored 't'/'f' text in this CSV-derived export. Always False —
  hard-set to False by normalize.py for every row (extracted["ageOnEdgeGenerated"]
  = False). Reserved/legacy flag distinguishing an on-device (edge) age
  estimate from the LLM read; currently always the LLM read, so this field
  carries no variation in this dataset.

sex            [schema key: gen]
  Values: female | male | other | unknown
  Verbatim: "Read biological sex from the image. Distinct from aesthetic
  gender presentation (apparel, grooming, styling) — judge physiology
  only. Use physiological cues — facial structure, body proportions, hair.
  Unknown if sex cannot be determined from visible cues; prefer unknown
  over guessing. female=physiological cues indicate female — facial
  structure, body proportions, hair; male=physiological cues indicate male
  — facial structure, body proportions, hair; other=physiology is visible
  but matches neither typical male nor typical female cues; unknown=
  physiological cues insufficient to determine sex; prefer this over
  guessing"

sexOnEdgeGenerated
  Boolean, same status as ageOnEdgeGenerated — always False in this dataset.

is_staff       [schema key: staff]
  Boolean (1/0/NULL). Verbatim: "Decide whether this person is store staff
  rather than a customer; used to filter sessions before any downstream
  analysis — staff sessions should never enter the pipeline as shoppers."
  Note: every visitor already known/flagged as staff by the separate
  visitor_exclusions mechanism was removed from the population before this
  composite was built (see accompanying note.md, "population"); this
  column is the model's own per-photo staff read, kept as-is.

occupational_context   [schema key: occ]
  Values: none | healthcare | manual_trades | uniformed_authority |
  food_service | school_uniform | branded_workwear | delivery_logistics |
  unknown
  Verbatim: "Visible occupational context indicated by uniform, workwear,
  or distinctive occupational equipment; most shoppers wear civilian dress
  and should be classified as none; only flag when clear, unambiguous
  workwear or equipment is directly visible — do not infer occupation from
  style alone. none=civilian dress with no occupational indicators — the
  correct value for most shoppers; healthcare=scrubs, lab coat,
  stethoscope, nursing shoes, or other healthcare workwear visible;
  manual_trades=high-vis vest, hard hat, work boots, tool belt, or other
  trade workwear visible; uniformed_authority=police, military, security,
  or fire service uniform with visible insignia; food_service=chef whites,
  kitchen apron, or food service uniform visible; school_uniform=school or
  college uniform with identifiable institutional dress;
  branded_workwear=generic corporate uniform, branded polo shirt, or work
  fleece with company logo (non-trade); delivery_logistics=courier
  uniform, delivery vest, or logistics company branded outerwear;
  unknown=occupational cues present but type cannot be determined"

individual_activity    [schema key: act]
  Values: waiting | browsing | inspecting | comparing | reading | on_phone
  | paying | queueing | passing | unknown
  Verbatim: "Name what this shopper is primarily doing at the display;
  unknown if activity cannot be determined from the image. waiting=
  standing without engaging with products or display and not in a
  checkout line — idle rather than queueing; browsing=actively looking at
  products or display without picking anything up; inspecting=picking up
  or closely examining a specific item — high intent signal; comparing=
  evaluating two or more items side by side — highest intent signal;
  reading=reading a label, price tag, or product information; on_phone=
  primary attention on phone — may be checking prices, reviews, or
  distracted; paying=engaged in the payment or checkout interaction;
  queueing=standing in or moving along a checkout line — waiting for a
  turn to pay, not idling and not passing through; passing=moving through
  the area without stopping to engage; not waiting for anything;
  unknown=activity cannot be determined from the image"

B2. Social context — schema.py class SocialContext (section "2")
--------------------------------------------------------------------------------
Absent section 2 (i.e. the model reported no group) is normalized as
group_size=1, group_activity=NULL, group_gender_mix=NULL (solo shopper) —
NULL here means "not applicable to a solo shopper", not "unknown".

group_size     [schema key: size]
  Integer, always present (1 = solo). Verbatim: "Number of people in the
  shopper's group; always present — 1 = solo shopper; NULL only on LLM
  extraction failure."

group_activity [schema key: act]
  Values: no_interaction | talking | browsing | physical_interaction |
  selling | unknown (NULL when group_size=1)
  Verbatim: "Name how the shopper and their companion(s) are interacting;
  NULL when group_size=1 (not applicable for solo shoppers); unknown when
  group is present but interaction cannot be determined. no_interaction=
  multiple people present but no social connection — co-located strangers;
  talking=shopper and companion(s) talking, not actively shopping
  together; browsing=group casually looking at products together;
  physical_interaction=group actively handling or evaluating products
  together; selling=staff member actively selling to or assisting the
  shopper — strongest purchase intent signal; unknown=group present but
  interaction pattern cannot be determined"

group_gender_mix   [schema key: mix]
  Values: all_female | all_male | mixed_gender | unknown (NULL when
  group_size=1)
  Verbatim: "Gender composition of the group; NULL when group_size=1 (not
  applicable for solo shoppers); unknown when group gender cannot be
  determined. all_female=group composed entirely of women; all_male=group
  composed entirely of men; mixed_gender=male + female pair or
  mixed-gender group; unknown=group present but gender composition cannot
  be determined"

B3. Body / grooming detail — schema.py class Body (section "3")
Only the fields NOT superseded by brand-detector's body_archetype are kept
(golden's body_type and body_composition_archetype are dropped from this
dataset — see bd_body_archetype in Section C, and "fields intentionally
absent" at the end of this file).
--------------------------------------------------------------------------------

body_shape     [schema key: shape]
  Values: hourglass | pear | inverted_triangle | apple | rectangle |
  unknown
  Verbatim: "Read body shape from the outline of the torso; free-text in
  source, canonicalized to buckets. hourglass=shoulders and hips roughly
  equal width with a visibly narrower waist; pear=hips noticeably wider
  than shoulders; inverted_triangle=shoulders noticeably wider than hips;
  apple=weight carried at the midsection — the waist is the widest point,
  wider than both shoulders and hips; rectangle=shoulders, waist, and hips
  roughly the same width with little definition; a positive reading of a
  straight silhouette, NOT a fallback for an unclear one — use unknown for
  that; unknown=body not sufficiently visible to assess proportions — use
  liberally; this attribute is hard to assess from store cameras"

height         [schema key: ht]
  Values: short | average | tall | unknown
  Verbatim: "Judge height against an average adult population; do not use
  average as a fallback when uncertain — use unknown instead. short=
  visibly shorter than a typical adult — noticeably below average, not
  just slightly under; average=clearly typical adult height — only use
  when you can positively confirm an unremarkable height; NOT a fallback
  when uncertain; tall=visibly taller than a typical adult — noticeably
  above average, not just slightly over; unknown=height cannot be assessed
  from the image; prefer over average when unsure"

chest_size     [schema key: chest]
  Values: s | m | l | unknown
  Verbatim: "Upper-body chest width read from the torso itself — how the
  fabric sits across the shoulders and chest. Judge it independently of
  overall build: a heavy shopper can have a narrow chest and a slim one a
  broad chest, so do not read this off body_type. Do not use m as a
  fallback when uncertain — use unknown instead. s=visibly slim upper
  body, fabric hangs loosely or chest appears narrow relative to typical
  adult; m=clearly typical chest width — only use when you can positively
  confirm an unremarkable fit; NOT a fallback when uncertain; l=visibly
  broad or full chest, fabric appears stretched or fitted across the upper
  body; unknown=upper body not visible or chest size cannot be assessed"

skin_tone      [schema key: skin]
  Values: light | medium | dark | unknown
  Verbatim: "Read skin tone from exposed skin — face, hands, neck.
  light=pale to fair skin — minimal melanin, cool or neutral undertones;
  medium=tan to olive or warm brown skin — moderate melanin; dark=deep
  brown to dark skin — high melanin; unknown=skin not sufficiently visible
  to assess"

hair_colour    [schema key: h_col]
  Values: blonde | brown | ginger | black | grey | white | exotic |
  unknown
  Verbatim: "Dominant visible hair colour. blonde=light yellow to golden
  hair; brown=any shade of brown from light to dark; ginger=red or auburn
  hair; black=very dark brown to black hair; grey=mixed grey and natural
  colour, or fully grey; white=fully white or platinum hair; exotic=
  clearly dyed in an unnatural colour — blue, pink, green, purple, etc.;
  unknown=hair not visible, fully covered by headwear, or colour
  indeterminate in the available light"

hair_length    [schema key: h_len]
  Values: no_hair | short | medium | long | unknown
  Verbatim: "Visible hair length. no_hair=bald or fully shaved head;
  short=above the ear or close-cropped — ear and neck fully visible;
  medium=ear to shoulder length; long=below the shoulder; unknown=hair not
  visible or length cannot be assessed"

hair_texture   [schema key: h_tex]
  Values: straight | wavy | curly | unknown
  Verbatim: "Read hair texture from the visible hair; free-text
  canonicalized to descriptive buckets. straight=hair lies flat without
  curl or wave — includes blow-dried or chemically straightened; wavy=
  loose S-shaped curves or bends; curly=defined curls or coils; unknown=
  hair not visible, obscured by headwear, or texture indeterminate"

hair_style     [schema key: h_sty]
  Values: loose | fringe | ponytail | bun | braid | updo | cropped |
  buzz_cut | afro | dreadlocks | unknown
  Verbatim: "How the hair is ARRANGED, not how long it is — length is
  recorded separately in hair_length and texture in hair_texture, so do
  not restate either here. Pick the arrangement that is actually visible;
  when the hair is simply worn without arrangement, choose loose or
  cropped according to its length. loose=worn down and unarranged, any
  length — no tie, clip, or deliberate shaping; fringe=hair falls across
  the forehead as the defining feature; when the fringe sits alongside a
  tied arrangement, record the arrangement instead; ponytail=hair pulled
  back and tied at the nape or crown; bun=hair twisted or coiled into a
  compact form, including topknots; braid=single or multiple plaits;
  updo=hair pinned or arranged up — more formal or elaborate than a bun;
  cropped=too short to arrange but cut and shaped — side-parted, textured,
  or swept; buzz_cut=clipped to uniform stubble over the whole head, with
  no shaping; afro=natural volume forming a rounded shape around the head;
  dreadlocks=hair formed into rope-like strands; unknown=hair style not
  visible or cannot be determined"

facial_hair    [schema key: f_hair]
  Values: no_hair | stubble | moustache | goatee | beard | unknown
  Verbatim: "Name the facial hair you can see; free-text canonicalized to
  canonical styles. no_hair=clean-shaven or no visible facial hair;
  stubble=short unshaven growth, a few days old — not yet a formed beard;
  moustache=facial hair on the upper lip only; goatee=hair on the chin
  with or without moustache; cheeks clean; beard=substantial facial hair
  covering most of the lower face; unknown=face not visible or facial
  hair status cannot be determined"

skin_condition [schema key: sk_cond]
  Values: clear | blemished | unknown
  Verbatim: "Read overall skin condition from the visible skin. clear=
  smooth, even skin with no visible blemishes or discolouration;
  blemished=any visible deviation — acne, spots, redness, uneven tone, or
  discolouration; unknown=face not clearly visible or skin condition
  cannot be assessed at this resolution"

skin_weathering [schema key: sk_weather]
  Values: indoor_pale | neutral | sun_exposed | weathered | unknown
  Verbatim: "Visible degree of sun/wind exposure on skin, separate from
  skin_tone (pigmentation) and skin_condition (acne/clarity). Cumulative
  weathering reflects outdoor habitual exposure — strong corroborating
  signal for habitual activity orientation. indoor_pale=clearly
  unweathered, indoor-lifestyle skin — no visible tan, sun damage, or wind
  exposure; neutral=a positive reading of ordinary incidental sun exposure
  — skin shows neither pallor nor tan. Not a middle-ground default: when
  the skin does look pale or does look tanned, say so; sun_exposed=
  visible tan lines, sun-darkened areas, or moderate sun-exposure markers
  without long-term damage; weathered=deep cumulative weathering —
  leathery texture, deep tan, sun-aged skin; signals long-term
  outdoor/manual lifestyle; unknown=skin not sufficiently visible to
  assess weathering"

has_tattoos    [schema key: tattoo]
  Boolean (1/0/NULL). Verbatim: "Say whether a tattoo is visible on this
  person. true when ink on skin is visible anywhere in frame, including a
  partially obscured or small piece. false when skin is visible and
  carries no ink. null only when essentially no skin is visible. Do not
  infer from style or dress."

has_piercings  [schema key: pierce]
  Boolean (1/0/NULL). Verbatim: "Say whether a piercing is visible on this
  person. true for jewellery worn through skin — ears, nose, septum, lip,
  brow, or elsewhere; ordinary earrings count. false when the relevant
  areas are visible and bare. null only when ears and face are both not
  visible."

has_visible_marks [schema key: marks]
  Boolean (1/0/NULL). Verbatim: "Say whether a distinctive mark is visible
  on this person. true when a scar, birthmark, prominent mole, burn, or
  vitiligo patch is visible on skin. Transient or artefactual things are
  not marks and are false: dirt, makeup, shadow, wet skin, motion blur,
  and JPEG compression noise. false when skin is visible and unmarked.
  null only when no skin is visible at all."

has_notable_nails [schema key: nails]
  Boolean (1/0/NULL). Verbatim: "Say whether this person's nails are
  notable. true when nails are long, painted, french-manicured,
  decorated, sculpted, or otherwise distinctive enough to read as a
  deliberate choice. Plain, short or bitten unpainted nails are false, not
  null — an ordinary hand is an observation, not a missing one. null only
  when no hand or fingertip is visible."

makeup_visible [schema key: makeup]
  Values: none | subtle | prominent | theatrical | unknown
  Verbatim: "Read makeup at face level — eyes, lips, cheeks, brows.
  Independent of skin_condition (which captures clarity/blemishes) and
  has_notable_nails (which captures hand-grooming). Primary direct signal
  for feminine-pole gender presentation when present, but absence does NOT
  signal masculine — many feminine-presenting shoppers wear no makeup.
  none=no visible makeup — bare face or imperceptible grooming-only
  product use; subtle=light everyday makeup — minimal foundation, neutral
  lip, light brow definition; reads natural at a casual glance; prominent=
  clearly visible makeup — defined eye makeup, bold lip colour, contoured
  cheeks, or other clearly-applied looks; theatrical=heavy or stylised
  makeup — full glam, dramatic eye, bold lip combined with strong contour,
  or stage-style application; unknown=face not sufficiently visible to
  assess makeup"

grooming_state [schema key: groom]
  Values: high | standard | minimal | unkempt | unknown
  Verbatim: "Holistic assessment of personal grooming and upkeep level
  visible across hair, facial hair, skin, and nails as a whole.
  Independent of which gender direction the grooming goes — captures HOW
  MUCH effort is visibly invested in personal upkeep, not which
  presentation it supports. high=clearly high effort visible — hair
  styled or carefully kept, facial hair groomed (or clean-shaven by
  choice), skin appears cared-for, polished overall personal upkeep;
  standard=typical everyday upkeep — clean and tidy without notable
  styling or extra effort; the default observable state; minimal=
  low-effort upkeep — hair functional but not styled, basic grooming, no
  styling investment visible; unkempt=visibly low or no upkeep — bedhead,
  unkempt facial hair, dishevelled overall appearance; unknown=face/head
  not sufficiently visible to assess grooming"

(golden `preg` / visible_pregnancy is dropped from this dataset — see
bd_visible_pregnancy in Section C.)

B7. Holistic gestalt impressions — schema.py class Impressions (section "11")
All fields in this section are kept in full (none dropped).
--------------------------------------------------------------------------------

apparent_spending_tier   [schema key: spend]
  Values: luxury | premium | mid_range | budget | unknown
  Verbatim: "Apparent overall spending tier inferred from visible signals
  — clothing quality, fit, accessories, and brands serve as observable
  proxies for general spending capacity, not a measure of appearance spend
  specifically. luxury=visibly premium materials and construction —
  designer brands, bespoke fit, high-end accessories; overall appearance
  signals significant discretionary spend; premium=quality materials and
  considered styling — polished, well-fitted, deliberate choices; may or
  may not carry visible brands but overall finish signals above-average
  spend; mid_range=standard mass-market appearance — basic fit and
  condition, no quality cues in either direction; generic and
  unremarkable presentation; budget=visibly low-cost — ill-fitting, worn,
  or clearly low-quality materials; fast-fashion appearance; unknown=the
  outfit is not visible enough to read material quality or finish — a
  legitimate answer, not a failure; prefer it over guessing mid_range"
  NOTE: kept as a deliberate cross-check pair against bd_spending_signal
  (Section C) — same whole-outfit construct, read independently by two
  different models/prompts/schemas from the same photo.

gender_expression   [schema key: gen_exp]
  Values: feminine | feminine_leaning | androgynous | masculine_leaning |
  masculine | unknown
  Verbatim: "The gender aesthetic projected through STYLING CHOICES ONLY —
  garment cut, colour, accessories, grooming, and hair treatment.
  Physiology is explicitly out of scope: face shape, body proportions, and
  apparent sex must not influence this value, which is recorded separately
  in `sex`. A masculine-presenting woman is masculine here; a man in
  decorative, fitted, or expressively groomed styling is feminine or
  feminine_leaning. If the answer merely restates `sex`, the styling
  evidence has not been examined. feminine=presentation clearly indexes to
  traditional feminine styling — dresses, heels, decorative accessories,
  long styled hair, expressive grooming; feminine_leaning=more feminine
  than neutral but not unambiguously so — e.g. fitted clothing, handbag,
  some jewellery alongside neutral pieces; androgynous=balanced or
  intentionally gender-neutral presentation — styling cues do not lean
  clearly toward either feminine or masculine conventions;
  masculine_leaning=more masculine than neutral but not unambiguously so —
  e.g. structured outerwear, functional footwear, minimal accessories;
  masculine=presentation clearly indexes to traditional masculine styling
  — suits, structured jackets, close-cropped hair, no feminine styling
  cues; unknown=gender expression cannot be assessed from the image"

subcultural_alignment   [schema key: subcult]
  Values: classic | minimalist | streetwear | goth | punk | granola |
  grunge | bohemian | glamorous | mainstream | unknown
  Verbatim: "The aesthetic subculture or tribe the shopper's overall look
  belongs to; requires pattern-matching across multiple visual cues into a
  named aesthetic. classic=polished, heritage, conservative styling —
  structured pieces, neutral palette, understated accessories;
  minimalist=intentionally simple and clean — monochrome or tonal palette,
  minimal accessories, clean silhouettes; streetwear=urban, logo or

keywords_json
  JSON object. Structure: {<dimension_name>: {"keywords": [<string>, ...]}}
  for each of the 9 dimensions listed below. 3-7 short English kebab-case
  noun phrases per dimension, produced in one open-ended structured pass
  over the whole photo (distinct from and in addition to the closed-enum
  section 1-11 fields above). Per the schema class docstring: "Open-ended
  structured keyword sweep across 15 commercial-relevance dimensions" —
  note the class currently defines 11 dimensions total (2 of which,
  apparel_items/apparel_brand_logo, are removed here); "Be brutally
  honest and specific — no generic placeholders, no synonyms within a
  dimension. When a dimension has nothing to say, still produce 3
  keywords at the lowest applicable confidence." Some rows may carry a
  legacy nested {"keywords": [...], "confidence": 0|1|2} shape per key
  instead — see analysis-api/libs/datalayer/transforms/normalize.py
  _recombine_s12 for the exact historical shape variants.

  Dimensions present, each with its verbatim per-field description:

  demographic_observable — "[observable] Visible demographic descriptors
    that ADD SIGNAL beyond section 1. Section 1 already captures sex
    (male/female/other/unknown) and age decade — do NOT emit keywords
    like 'male', 'female', 'male-shopper', 'middle-aged', '30s'. Focus on
    physique, hair (color/length/style), facial hair, skin tone/
    condition, distinguishing features."

  grooming_presentation — "[observable] Upkeep and polish level —
    well-groomed, scruffy, polished, salon-fresh, just-woke-up."

  material_color_signal — "[observable] Distinctive materials, colors, or
    color combinations that carry signal — hi-vis-yellow, faded-denim,
    leather-tan, technical-fabric."

  style_archetype — "[inferred] Aesthetic taste cluster — streetwear,
    business-casual, gorpcore, dad-style, normcore, prep, techwear. Pick
    the closest existing label even if imperfect."

  subculture_signal — "[inferred] Recognizable cultural or lifestyle
    tribe — hypebeast, tradesman, biker, hiker, soccer-mom,
    retiree-gardener, outdoorsman."

  economic_signal — "[inferred] Affluence cues — budget-conscious,
    mid-market, splurge-posture, conspicuous-luxury. Judge from apparent
    quality, brand mix, and condition — not pose."

  aspirational_projection — "[inferred] What the outfit projects
    intentionally — status-seeking, professional, anti-fashion, invisible,
    attention-seeking, nostalgic."

  life_context — "[inferred] Implied current life situation — commuter,
    on-shift-worker, weekend-errand, post-gym, school-pickup,
    on-vacation."

  social_role — "[inferred] Implied life role — tradesman, parent,
    student, retiree, white-collar-professional, gig-worker. Do NOT emit
    content-free placeholders like 'consumer', 'customer', 'shopper',
    'adult-shopper', 'solo-shopper' — those describe the act of shopping,
    not a life role. If no clear role is visible, use confidence=0 and the
    closest specific guess."

  (apparel_items and apparel_brand_logo dimensions are removed from this
  dataset's keywords_json — superseded by bd_items, Section C.)

  browsing needs a real engagement cue (looking at goods, entering or
  exiting a shop, lingering), not just empty hands.
  immediate_consumption / top_up / stock_up / browsing / passing_through /
  service_only / unclear."
  NOTE: kept alongside golden's individual_activity (Section B1) as a
  complementary, not redundant, read — different construct (momentary
  verb vs. inferred whole-visit purpose), calibrated in-prompt for a
  shopping-centre concourse specifically.

C3. Item inventory — schema.py classes Item / Garment / Accessory / CarriedItem
--------------------------------------------------------------------------------

bd_items
  Type: JSON array of {"type": <string|null>, "brand": <string|null>}
  objects. Built by the join script (build_joined.py) by flattening BD's
  three separate arrays — garments[], accessories[], carried_items[] —
  into one list and keeping only the `type` and `brand` sub-fields of
  each; the source-array distinction (garment vs. worn accessory vs.
  carried object) is NOT preserved in this dataset once flattened, nor are
  each item's `evidence`, `brand_detail`, `brand_basis` or `price_tier`
  sub-fields (all present in the raw per-visitor JSON files under
  ops/cpi-brand-score-full/results/<person_id>.json, but intentionally
  excluded from the composite — see "fields intentionally absent" below).

  Per-object field meanings (verbatim, shared base description in
  schema.py class Item, then refined per array in Garment/Accessory/
  CarriedItem):

  type (garments[])   — "Garment type: the single most specific common
    noun or short noun phrase for what it is - lowercase snake_case, keep
    a pair or plural-only name as-is ('shoes', 'sneakers'), otherwise
    singular ('ring' not 'rings'), matching the specificity of your own
    evidence line. Not a broad category word when a specific one applies
    (a backpack is 'backpack', a crossbody purse is 'crossbody_bag' - not
    'bag'). Barefoot or minimalist shoes (wide toe box, flat zero-drop
    sole) are 'barefoot_shoes', not 'sneakers'."

  type (accessories[]) — "Worn-accessory type: the single most specific
    common noun for what it is - lowercase snake_case, keep a pair or
    plural-only name as-is ('shoes', 'sneakers'), otherwise singular
    ('ring' not 'rings'), matching the specificity of your own evidence
    line. Not a broad category word when a specific one applies (a
    digital watch is 'digital_watch', sunglasses are 'sunglasses' - not
    'watch' or 'eyewear')."

  type (carried_items[]) — "Carried-item type: the single most specific
    common noun for what it is - lowercase snake_case, keep a pair or
    plural-only name as-is ('shoes', 'sneakers'), otherwise singular
    ('ring' not 'rings'), matching the specificity of your own evidence
    line. Not a broad category word when a specific one applies (a gym
    holdall is 'sports_bag', a shoebox is 'box' - not a broader word that
    only roughly fits)."

  IMPORTANT — `type` is OPEN free text, not a closed enum, across all
  three arrays: the model names whatever it sees in its own words
  (normalized only to lowercase snake_case by a formatting-only regex,
  normalize_type() in brand_detector/schema.py — no synonym/plural
  unification, e.g. "shoe" vs "shoes" or "watch" vs "wristwatch" remain
  distinct raw strings). A reference vocabulary the model is NOT shown as
  a pick-list exists in schema.py for calibration only: GARMENT_TYPES,
  ACCESSORY_TYPES, CARRIED_ITEM_TYPES tuples — useful as a seed list for
  building your own canonicalization, not as ground truth for what values
  can appear.

  brand (all three arrays, same description) — "Brand name, or null only
    if you genuinely cannot tell, including from design signature."
    Free text, as normally written (not slugified/lowercased in this
    dataset — unlike golden's dropped per-category brand fields, which
    were lowercased at normalize-time; bd_items brand strings retain
    original casing as emitted by the model). null = no brand identifiable.

  What every array can contain, verbatim from Detection's own field
  descriptions (useful for interpreting which array an item most likely
  came from, even though the array split itself is not preserved in
  bd_items):

  garments[] — clothing worn on the body (shoes count as garments in bd's
    scheme, along with bags, hats and scarves per the accessories[]
    description below).

  accessories[] — "Small items worn on the body that are not principal
    clothing - a watch or smartwatch, a bracelet, necklace, ring or
    earrings, a rubber or fabric wristband, worn eyewear, worn earbuds or
    headphones, hair accessories, gloves. One object per item; list
    duplicates (e.g. two rings) as separate entries. Bags, hats and
    scarves are garments. Anything held or carried, not worn, is a
    carried_item. Empty list if nothing."

  carried_items[] — "Things held, pushed or led that are not worn - keys,
    a cup or bottle, a wallet, a payment card, a box or parcel, a shopping
    bag (name the shop if legible), a basket, luggage, a pushchair, a pet,
    a fuel nozzle, a walking stick or cane, a helmet carried in the hand, a
    wheeled or led bicycle. One object per item; list duplicates as
    separate entries. Name a phone only when it is the only object
    detected anywhere on the person - otherwise leave it out. A jacket
    over the arm or a shoulder bag is a garment entry, not this. Empty
    list if nothing."

  Multiple items of the same kind (two watches, three bags, N garments)
  each get their own separate entry in bd_items — unlike golden's
  per-category fields (one slot per category), bd's arrays are unbounded.

  absolute magnitude) and sessions_dominant (count of visitors in the full

  is NOT the same denominator as joined.jsonl's 54,092).

  DELIBERATELY EXCLUDED from this export: nmf_topic_v2 also stores `label`,
